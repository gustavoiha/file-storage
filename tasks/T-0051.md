# T-0051 Menus opened from the keyboard focus their first item
Issue: #109
Request: #65
Origin: T-0047
Status: review

## Goal
Opening a menu button from the keyboard (Enter or Space on the trigger) should move focus to the menu's first enabled item, as in the usual menu-button pattern. Today the shared `DropdownMenu` (`apps/web/src/components/ui/DropdownMenu.tsx`) leaves focus on the trigger by default until ArrowDown or Tab moves it into the menu (documented default since T-0007), so a keyboard or screen reader user who presses Enter on "Upload" gets no item announced and must press another key first. Affects every menu using the default (files page Upload, Dockspace / Folder options, row Actions, gallery menus). Found while testing T-0047 (#101), round 1, finding 2 (pre-existing on main).

## Acceptance criteria
1. Opening a `DropdownMenu` with Enter or Space on its trigger focuses the first enabled item (skipping separators and disabled items); menus that use `initialFocus="checked"` keep focusing the checked item.
2. Opening with a mouse click or touch does not show a focus ring on an item (the ring stays keyboard-only, as elsewhere in the app).
3. ArrowUp/Down, Home/End, wrap-around, Escape (focus back to the trigger) and click outside behave as today; the right-click / long-press row menus keep their current focus behaviour (T-0008).
4. Checked on the files page Upload menu (desktop and the phone floating button), Dockspace options, a row Actions menu, and one gallery menu. Unit test for keyboard opening. Build, typecheck and tests pass.
