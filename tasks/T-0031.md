# T-0031 Gallery: show loading status while a background refetch delays the next page
Issue: #69
Request: #65
Origin: T-0029
Status: engineering

## Goal
In the media gallery, automatic loading of the next page waits while any background refetch of the media query runs (window focus after `staleTime`, or an invalidation after an upload, trash or album change). A refetch re-requests every loaded page one after another, so with several pages loaded it can take a few seconds. During that wait the reserved footer (`role="status"`) in `apps/web/src/pages/dockspaceMedia/VirtualizedMediaGrid.tsx` is empty, because its text shows only for `isFetchingNextPage`, so a user who reaches the unloaded bottom gets no feedback until the next page arrives.

## Acceptance criteria
1. While a background refetch of the media query runs, there is a next page and no remembered next-page error, the footer's `role="status"` region shows "Loading more media..." (the footer space is already reserved, so tile layout does not change).
2. The text is cleared when nothing is loading, and is not shown while the next-page error with Try again is shown, nor in album views.
3. The held-refetch test in `DockspaceMediaPaging.test.tsx` expects the status text while the refetch runs and the next page request after it ends. Build, typecheck and tests pass.

## Review decisions (round 1)
- PR #71 at `d29434d`. Findings: C1 (code review); security review had none. No new tasks.
- C1 **critical**: confirmed at `VirtualizedMediaGrid.tsx:176`. `showLoadingStatus` ignores scroll position, so this PR makes the polite `role="status"` region announce "Loading more media..." on every background refetch with a next page (each upload, trash, album change, tab return), wherever the user is. Before the PR nothing was announced then, so screen reader users get a new, false message in normal use. The goal is feedback for a user who reached the unloaded bottom, so narrowing the refetch case to the load-ahead distance keeps AC1's intent. Fix in this PR: show the refetch case only when `remainingPx <= loadAheadPx` (the check the load effect uses), keep `isFetchingNextPage` as is, and add a test that the status stays empty during a refetch while scrolled to the top (the held-refetch test still expects the text at the bottom).
