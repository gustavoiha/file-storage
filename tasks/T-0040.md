# T-0040 Gallery Move to trash dialog: focus on open, Tab trap, focus after close
Issue: #84
Request: #65
Origin: T-0034
Status: review

## Goal
The media gallery's Move to trash confirmation dialog (`apps/web/src/pages/dockspaceMedia/DockspaceMediaWorkspace.tsx`, `aria-modal="true"`, used by Trash selected in the gallery and by Move selected to trash in Find duplicates) does not take focus when it opens and does not keep Tab inside, so Tab walks to the controls behind the modal (Upload media, Cancel selection, ...). After a confirmed trash, focus falls to the page body: in the gallery the selection mode ends and the Trash selected opener is unmounted; in Find duplicates the opener is disabled. Already on main. Found while testing T-0034 (#75), round 1, findings 1 and 2.

Notes: follow the confirmation dialogs' pattern on the files and trash pages (T-0020 focus on open and document-level Tab trap, T-0022 focus after a failed submit) and the engineering lesson on dialog-confirmed removal. The Add to album dialog in the same file has `autoFocus` but no Tab trap; share the trap with it if cheap. T-0030 (PR #73) restructures the selection bar in the same file and T-0034 (PR #78) changes when the dialog closes: build after both are merged, rebase on main before the PR.

## Acceptance criteria
1. Opening the dialog (gallery Trash selected, Find duplicates Move selected to trash) moves focus to Cancel; Tab and Shift+Tab stay inside the dialog, also while "Moving..." and after a failed request.
2. After a confirmed trash, focus goes to a stable control, never the page body: in the gallery for example the control that replaces the selection bar, in Find duplicates the duplicates list or its heading. Visible ring for keyboard users only (`:focus-visible`).
3. Escape, Cancel and the backdrop still close the dialog and return focus to the opener; the trash behaviour itself (T-0034: closes as soon as the trash request succeeds) is unchanged.
4. Unit tests cover focus on open, the Tab trap and focus after close in both contexts; no new axe violations on desktop and phone. Build, typecheck and tests pass.
