# T-0030 Gallery layout: no card frame, actions in a menu, gapless grid
Issue: #67
Request: #65
Status: testing

## Goal
Make the media gallery page use its space for the media. Today the main panel is a card (`.media-workspace__main` in `apps/web/src/styles/layout.css`: border, 10px radius, padding, own background), the always-visible 320px sidebar (`DockspaceMediaWorkspace.tsx`: Actions = Find duplicates / Browse media, Trash, Detailed usage; Albums = All media + each album with its count; Uploads = active uploads with retry and skipped duplicates with Dismiss) takes a column on desktop and stacks under the gallery on phone, and the grid has a 12px gap (`MEDIA_GRID_GAP_PX`) with 12px rounded, bordered tiles (`.media-card`). The human wants no card frame, the sidebar replaced by a menu, and tiles rendered without gaps or rounded borders. Where albums, uploads and the actions live once the sidebar is gone is a layout decision, so this goes to design first.

## Acceptance criteria
1. The gallery main area has no card frame: no border, radius, inner padding or separate panel background around the grid; the grid spans the full content width (edge to edge on phone).
2. The sidebar is not always visible on desktop or phone. Its contents are reachable from a menu (exact form per the chosen design), and everything stays reachable: Find duplicates / Browse media, Trash, Detailed usage, switching between All media and each album (with counts and the current one marked), and the uploads list (progress, retry, skipped duplicates with Dismiss). Active uploads stay noticeable while the menu is closed (e.g. a count or progress on the toolbar).
3. Grid tiles are square with no gap between them, no rounded corners and no border. Selected tiles and keyboard focus stay clearly visible (inset ring or overlay, not a border that reintroduces a gap); hover does not move the tile.
4. Unchanged: grid size toggle, upload button, multi-select with bulk Add to album / Trash selected / Cancel, preview with previous/next, the duplicates view, and T-0029's loading and scroll behaviour.
5. Accessibility: the menu opens and closes by keyboard (Escape closes and returns focus to its trigger), has an accessible name, and the page has no new axe violations on desktop and phone.
6. Unit tests updated for the new structure. Build, typecheck and tests pass.

## Code review (round 1)
PR https://github.com/gustavoiha/file-storage/pull/73 at b2a657f. Checked against the final design and engineering-lessons. No blocking findings. The album menu, ⋯ Gallery options, floating uploads card, square gapless grid and focus moves (menu choice → trigger, Select items → Cancel, Cancel → album button, Dismiss → Upload, Retry → Collapse) match the spec and have tests. The DropdownMenu type-ahead runs only while focus is inside an open menu, and no existing menu contains a text input, so it does not take over typing elsewhere. The selected+focus combined rule comes after the state rule, as the lessons require.

- **C1 (non-blocking): in browse mode, the last opened tile looks multi-selected.** `apps/web/src/pages/dockspaceMedia/VirtualizedMediaGrid.tsx:197-212` sets `data-selected` from `selectedMediaId === item.fileNodeId` when selection mode is off. `onOpenPreview` sets that id and closing the preview never clears it. The new `.media-card[data-selected='true']::after` rule (`layout.css:2985`: 24% blue tint plus a 3px accent inset ring) now draws that tile exactly like a multi-select pick, without the check. On main it was a faint border tint. Next/previous inside the preview do not move `selectedMediaId`, so the highlight stays on the first tile opened, not on the one the user ended on. Why it matters: criterion 3 says selection must be clearly readable, and a browse-mode tile that looks selected says the wrong thing. Fix: set `data-selected` only while `isMultiSelectMode` is on, and use a separate attribute with a subtler style if the opened tile should stay marked.
- **C2 (non-blocking): the row size depends on whether a scrollbar is showing, which can make the grid flicker.** `VirtualizedMediaGrid.tsx` takes the width from `element.clientWidth`, and square rows make the row height (and so the total height) follow that width. With classic scrollbars (Windows, Linux, or macOS set to "always show"), the following loop can repeat every frame: content just taller than the box → a scrollbar appears → the width shrinks by about 15px → rows get shorter → the content fits → the scrollbar goes away → rows grow again. It only happens when the content height falls in a band of rows × 15 / columns px around the box height, but that is crossed while pages load and while the window is resized. Fix: add `scrollbar-gutter: stable;` to `.media-grid-virtual` (`layout.css:2876`) so the width does not change when the scrollbar appears.
- **C3 (non-blocking, a11y): in Windows forced-colors (high contrast) mode, tile focus and selection are invisible.** `.media-card:focus-visible { outline: none }` (`layout.css:2975`) leaves the `::after` `box-shadow` as the only indicator, and forced-colors mode removes box-shadows. On main, tiles kept the browser's default outline. Fix: use `outline: 2px solid transparent; outline-offset: -2px;` in place of `outline: none` (invisible normally, drawn in system colours in forced-colors mode). Optionally add an `@media (forced-colors: active)` outline for `[data-selected='true']`.
- **C4 (non-blocking, cleanup): `localError` is now dead state.** `useDockspaceMediaController.ts:24` still declares `[localError, setLocalError]`, but `setLocalError` is no longer called anywhere (its only use moved to `uploadSelectionError`). That makes `localError` in `hasAlerts` and the `<Alert message={localError} />` in `DockspaceMediaWorkspace.tsx:329,348` unreachable. Fix: remove the state, the returned field and the dead alert branch.

Security: nothing noticed (frontend layout only; no new data flows).

## Review decisions (round 1)
