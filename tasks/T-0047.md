# T-0047 Files upload: keep the skipped-files notice when some files still upload
Issue: #101
Request: #65
Origin: T-0043
Status: review

## Goal
On the files page, when an upload selection mixes valid files with files whose upload paths are invalid, the skipped-files notice ("1 file had an invalid upload path and was skipped." / "N files had invalid upload paths and were skipped.") is cleared almost at once, so the user is never told that some files were skipped. In `apps/web/src/hooks/useDockspaceUploadDialog.ts`, `stageFiles` and `stageFolderFiles` set `validationError`, then `enqueueUploads` (called for the valid files) resets it to `null`. File uploads never show the notice; folder uploads show it only while "Creating folders..." runs. The notice only stays when every selected file is invalid. Found while testing T-0043 (#93), round 1, finding 1 (pre-existing on main; also noted by engineering in T-0043).

## Acceptance criteria
1. A mixed valid/invalid selection on the files page (both "Upload files" and "Upload folder") shows the skipped-files notice in the Uploads card, and it stays visible while the valid files upload, until the next selection (same lifetime as when every file is invalid).
2. The valid files still upload; a selection with only valid files shows no notice and clears an older notice, as today.
3. Other messages in the same slot (folder creation failure, upload errors) keep their current behaviour.
4. A unit test covers a mixed selection on both staging paths, checking the notice is still set after the valid files are enqueued. Build, typecheck and tests pass.

Note: T-0045 (#96) changes how the collapsed phone pill reports a skipped-files notice (same Uploads card); check its state before building.

## Code review (round 1)

No AGENTS.md, data or pluralization concerns (message still from `invalidUploadPathsMessage`).
- **C1 (non-blocking)** `apps/web/src/pages/DockspaceFilesPage.tsx:1637` with `apps/web/src/components/files/UploadsCard.tsx:107,117` (on main): the files page passes the skipped-files notice as `uploadErrorMessage`, and the card counts any `uploadErrorMessage` as a failure. Fix: once T-0045 (PR #103, which adds `uploadNoticeMessage` to `UploadsCard`) is merged, pass the hook's invalid-path notice through that notice slot on the files page (and the gallery, which uses the same hook) instead of `uploadErrorMessage`; this can be a follow-up task rather than a change to this PR, since #103 is still open.
