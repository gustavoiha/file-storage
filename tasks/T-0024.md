# T-0024 Failed folder listing shows the error without the empty state
Issue: #52
Request: #31
Origin: T-0015
Status: new

## Goal
On the dockspace files page, opening a folder whose listing request fails shows the "Request failed" alert together with the empty state ("This folder is empty" / "Upload your first files"). The folder is not known to be empty, so the empty state and its upload call to action are wrong there. Today the file list gets the empty state whenever the listing is not loading (`emptyState={filesQuery.isLoading ? ... : emptyDockspaceState}` in `apps/web/src/pages/DockspaceFilesPage.tsx`), also after an error.

## Acceptance criteria
1. When the current folder's listing request fails, the page shows only the error (with a way to try again), not "This folder is empty" or "Upload your first files". Same on desktop and phone.
2. A folder that loads with no items still shows the empty state as today.
3. After a successful retry, the folder shows its contents, or the empty state if it really is empty.
4. The error is announced (`role="alert"`) and the retry control is keyboard reachable; focus does not fall to `body` when the retry starts or ends.
5. Unit tests cover the failed listing (no empty state), the truly empty folder and the retry. Build, typecheck and tests pass.

## Notes
