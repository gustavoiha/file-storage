# T-0049 Files page uploads pill: skipped invalid-path files are a notice, not a failed upload
Issue: #106
Request: #65
Origin: T-0047
Status: review

## Goal
On phone the files page's uploads card starts collapsed. The files page passes the upload hook's skipped-files notice ("1 file had an invalid upload path and was skipped." / "N files had invalid upload paths and were skipped.") to `UploadsCard` as `uploadErrorMessage`, and the card counts any `uploadErrorMessage` as a failure. So when a selection mixes valid files with invalid-path files (common since T-0047 keeps the notice while the valid files upload), the collapsed pill shows the red failure dot and its accessible name says "an upload failed" while the valid files upload fine, and the pill stays with the dot after they finish. The expanded card also shows the notice in error styling. T-0045 (#96, PR #103) adds an `uploadNoticeMessage` slot to `UploadsCard` for skipped-files notices; the files page should route the invalid-path notice through it. Found in review of T-0047 (#101), round 1, finding C1.

## Acceptance criteria
1. On the files page, a selection with invalid-path files (mixed with valid files, or only invalid) shows the skipped-files notice in the Uploads card as a notice: the collapsed pill does not show the red failure dot or say "an upload failed"; the expanded card shows the notice in the notice style, in the same place.
2. Real errors on the files page (folder creation failure, failed uploads, upload error messages) still show as errors, with the red dot and "an upload failed". When a real error and a skipped-files notice happen together, the error is still reported.
3. The gallery (same upload hook) keeps correct error vs notice reporting for anything it shows from the hook.
4. Unit tests cover the files page phone pill for a mixed selection (notice, no failure) and for a real failure. Build, typecheck and tests pass.
