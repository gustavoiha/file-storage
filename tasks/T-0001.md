# T-0001 File navigability: single folder view, parent context, side preview
Issue: #5
Status: filtering
Origin: human issue https://github.com/gustavoiha/file-storage/issues/5

## Goal
Make navigating files in a generic dockspace (route `/$dockspaceId`, `apps/web/src/pages/DockspaceFilesPage.tsx`) feel coherent:
- Today the folder structure appears twice: the folder tree in `DockspaceSidebar` (right-hand sidebar, also hosts upload controls/status) and the folder rows + breadcrumbs in `FileList` (main panel). The human wants exactly one place.
- When a nested folder is open, the human wants to still see the previous (parent) folder's contents, not just a breadcrumb (e.g. a column/Finder-style view; exact layout is a design decision).
- File preview currently opens as a modal `FileViewerDialog` (uses `FilePreviewContent`). The human wants the preview shown in a panel to the right of the file listing instead of a popup.

Out of scope: the media dockspace page (`DockspaceMediaPage`, album-based, uses `FileViewerDialog` variant `media-fullscreen`), trash and usage pages, backend changes.

## Acceptance criteria
1. On the generic dockspace files page, the folder hierarchy is rendered in exactly one place; no second folder tree / folder list duplicates it. Upload controls and upload progress/skipped/error status that live in `DockspaceSidebar` today remain reachable and functional.
2. When a folder at depth >= 1 is open, the contents (at least the folder entries) of its parent folder are visible on screen at the same time as the open folder's contents, with the open folder visually marked as selected in the parent. Clicking another folder in the parent switches to it.
3. The user can always navigate back to the dockspace root and to any ancestor in one click.
4. Clicking/opening a file shows its preview (the same content types `FilePreviewContent` supports today: images, video, audio, PDF, text, fallback) in a panel to the right of the listing, not in a modal overlay; the listing stays visible and interactive. The panel shows the file name, a download action and a close control; Escape closes it. Opening another file replaces the preview.
5. Existing file/folder actions keep working from the new layout: multi-select + move, rename, move to trash, download (file and folder), folder rename/move/trash, add folder, upload files/folder, empty-folder state.
6. Navigating to a different folder closes or updates the preview so it never shows a file that is not in the visible listing context (design decides which).
7. At phone width (<= 480px) the layout remains usable with no horizontal page scroll: e.g. preview takes the full width with a back control, and parent context collapses gracefully.
8. The media dockspace page's fullscreen viewer is unchanged.
9. Existing web tests pass; tests added/updated for the single navigation location, parent-folder visibility and side-panel preview.

### Page structure (route `/$dockspaceId`, `DockspaceFilesPage`)
Top to bottom: TopNav (unchanged), then the **folder bar**, then the **work area** (columns + preview). It fills the viewport height under the nav. The page body never scrolls horizontally, and each column scrolls vertically on its own.
- **Remove `DockspaceSidebar` from this page entirely**, along with its folder tree state (`expandedFolderNodeIds`, `loadingFolderNodeIds`, `sidebarFolderTree`, `onToggleSidebarFolder`, and the tree-building helpers if nothing else uses them). Folder discovery that the Move dialogs' FolderPicker relies on (`discoveredFoldersByNodeId` etc.) must keep working. The upload UI moves to a new `UploadsCard` component (see below). The old `FileList` breadcrumbs (`dockspace-browser__breadcrumbs`) and the separate folder rows above files are replaced by the columns. There must be exactly one breadcrumb and one place that lists folders per level.
- **Remove the `FileViewerDialog` usage from this page** (keep the component: `DockspaceMediaPage` still uses it, variant `media-fullscreen`, unchanged).

### Folder bar (desktop and tablet, > 900px)
- Left: breadcrumb `<nav aria-label="Folder path">`. First crumb: house icon + dockspace name (root). Then each ancestor as a `<button>`, separated by "/". The current folder is the last crumb, rendered as text with `aria-current="page"` (not a button). Long paths wrap onto a second line; never truncate the root or the current crumb. Clicking a crumb opens that folder (one click to the root or any ancestor).
- Right, in this order: `New folder` (secondary Button, folder-plus icon; opens the existing AddFolderDialog in the current folder), `Upload` (primary Button with a chevron; a DropdownMenu with `Upload files` and `Upload folder`, which trigger the existing hidden file/folder inputs; `aria-haspopup="menu"`), and the `⋯` "Dockspace options" menu, which now holds only `Trash` and `Detailed usage` (Create folder/Upload items are removed from it because they are in the bar).

### Columns (desktop/tablet)
- Container: `role="group" aria-label="Folder columns"`, a horizontal flex strip with `overflow-x: auto` (only the strip scrolls, not the page). When the trail changes, scroll the strip so the current column is fully visible (`scrollIntoView({inline: 'end'})` or set `scrollLeft`).
- One `<section aria-label="{folder name}">` per level of the trail: root, each ancestor, then the current folder. Data per column comes from `useFiles(dockspaceId, folderNodeId)` for that level (React Query caches these, so ancestor columns are usually instant). Show a small inline loading state ("Loading…") in a column whose query is pending, and an Alert on error.
- **Ancestor columns** (every level except the current one): fixed width 240px. Header: the folder name as an uppercase muted label (root shows the dockspace name). Rows: folders first (folder icon, name, chevron), then files (file-type icon, name, formatted size, no date), both sorted the same way as today. The folder that is next in the trail is highlighted (`aria-current="true"`, a selected background plus a 3px accent bar on the left, and an open-folder icon). Clicking any folder in an ancestor column opens it: the trail is cut to that column's level and the folder is appended, so clicking a sibling switches to it. Clicking a file in an ancestor column opens that column's folder as current and previews the file. Ancestor columns have no checkboxes or row menus.
- **Current column**: `flex: 1`, min-width 380px (≥ 1200px) or 280px (901–1199px). Header: "{Folder name} · N folders, M files" on the left, plus column labels "Size" and "Modified" aligned with the row values. It keeps the existing `FileList` behavior:
  - folder rows: icon, name, file count when known ("6 files"), chevron, and a `⋯` menu (`Actions for {name}`): Rename, Download, Move, Move to trash (the existing handlers);
  - file rows: icon that turns into a checkbox on hover/focus and while any file is selected (as today, `aria-label="Select {name}"`), name, formatted size (e.g. "2.9 MB", not bytes), Modified date ("Sep 15, 2025", from `updatedAt`), and a `⋯` menu: Rename, Download, Move to trash. The `⋯` triggers are visible on row hover/focus-within and always visible on touch/phone;
  - pending upload rows and pending folder rows with spinners, as today;
  - the selection bar ("N files selected", Move, Cancel) is pinned at the top of the current column, under its header;
  - empty folder: the existing empty-state illustration and "Upload your first files" inside the current column. An empty dockspace root shows the same in the single root column.
- Clicking a file row opens the preview for it. The previewed row gets `aria-current="true"` and the selected background + left accent bar (the whole row, including the menu cell).
- At depth 0 (root open) there is only the root column, and it is the current column.

### Preview column
- `<aside aria-label="File preview">`, width 420px at ≥ 1200px and 340px at 901–1199px, right of the columns, with a left border. It exists only while a file is open. When it closes, the current column takes the freed width.
- Header: file-type icon, file name as `<h2>` (ellipsis + `title` attribute when too long), `Download` (secondary small Button, existing `onDownloadFile`), and a close icon button `aria-label="Close preview"`.
- Body (scrolls on its own): `FilePreviewContent` (unchanged; images, video, audio, PDF, text, fallback), then a details list `<dl>`: Size (formatted), Type (content type, human readable when easy, else the MIME type), Modified, Location (the folder path using the dockspace name for the root). Footer hint: "<kbd>Esc</kbd> closes the preview".
- Behavior: opening another file replaces the preview, and the panel stays in place. Escape closes it unless a dialog or dropdown menu is open (those consume Escape first). On open, focus does not jump (the listing stays interactive). On close via X or Escape, focus returns to the row of the file that was previewed if it is still in the DOM. It is not modal: no backdrop, no focus trap, and the listing stays clickable.
- **Navigation closes the preview** (AC6): any change of the current folder (breadcrumb, a column click, back on phone, a folder renamed/moved/trashed so the trail changes) clears the previewed file. The preview also closes when the previewed file is renamed, moved, or moved to trash, or disappears from the current folder's data. The one exception is the ancestor-file click above, which navigates and then opens that file.

### Uploads card (replaces the sidebar Uploads section; AC1)
- New component `UploadsCard`, floating `position: fixed; left: 16px; bottom: 16px; width: 320px; max-height: 50vh` (the list scrolls inside it), `--bg-elevated` background, border, 10px radius, shadow, z-index above the columns and below dialogs. `<section aria-label="Uploads" aria-live="polite">`.
- Shown only while there is something to show: active uploads, "Creating folders…", an upload error, or skipped duplicates. It disappears when all of these are empty.
- Header: "UPLOADS" label, a count pill ("3 active"), and a collapse toggle (`aria-expanded`, "Collapse uploads"/"Expand uploads"). Collapsed, it shrinks to a one-line pill: "Uploading 2 of 3 · 64%" (uploads in flight, overall progress), with a red dot when any upload failed. Clicking the pill expands it.
- Rows (same data as today's `UploadQueueRow`): path (ellipsis), status on the right: "Waiting", "64%" with a 4px progress bar under the row, or "Failed" in `--error` with a `Retry` small button (existing `onRetryUpload`). `uploadErrorMessage` shows in `--error` text. "Creating folders…" shows as a muted line.
- Skipped duplicates: "N file(s) skipped as duplicate(s) · Details", where Details is a disclosure button (`aria-expanded`) that reveals the list of paths, and `Dismiss` (existing `onDismissSkippedUploads`).

### Phone and narrow layout (≤ 900px, which covers AC7's ≤ 480px)
One folder at a time. No columns, no horizontal scrolling anywhere (check at 360px and 390px).
- Breadcrumb row: `<nav aria-label="Folder path">` with small wrapping links for the root (house icon + dockspace name) and every ancestor, each followed by "/". Hidden at the root.
- Header row: back icon button (`aria-label="Back to {parent name}"`, hidden at the root), current folder name as `<h1>` (ellipsis), and a `⋯` "Folder options" menu: New folder, Upload files, Upload folder, separator, Trash, Detailed usage.
- Parent context (depth ≥ 1): a band labelled "IN {PARENT NAME}" with wrapping chips, one per folder in the parent (data from the parent level's `useFiles`). The current folder's chip has `aria-current="true"`, the accent style and an open-folder icon. Tapping a chip switches to that sibling. When the parent has more than 8 folders, show the first 7 (always including the current one) and a "Show all (N)" chip that expands the band. Files of the parent are not shown on phone.
- Listing: the current folder's rows at full width with icon, name, and size (no date). The `⋯` menu is always visible (44px tap target). Checkbox selection, the selection bar (sticky at the top) and the empty state work as on desktop.
- Floating `Upload` button (primary, pill, bottom-right, 16px from the edges) opening the Upload files / Upload folder menu. The uploads card is collapsed to its pill at bottom-left by default on phone. Expanded, it becomes a full-width card (left/right 16px) above the Upload button.
- Preview on phone: tapping a file replaces the listing area (breadcrumb, header, chips, list) with the preview view, full width. Its header is a back icon button (`aria-label="Back to {folder name}"`), the file name, and Download, with no X (back closes it). Then the FilePreviewContent and the details list. This is an in-page view, not a dialog. Back or Escape returns to the list and restores the scroll position. Hide the floating Upload button and the uploads pill while the preview is open.

### Breakpoints summary
- ≥ 1200px: all trail columns (strip scrolls if they don't fit), current min 380px, preview 420px.
- 901–1199px: only the parent column and the current column are shown; older ancestors are reachable through the breadcrumb. Current min 280px, preview 340px.
- ≤ 900px: phone layout above.
Use CSS media queries (add them next to the existing 920px/720px ones in layout.css) plus a `matchMedia('(max-width: 900px)')` hook only where markup differs (phone preview view vs. side panel).

### Accessibility
- Every interactive row is a real `<button>`, and menus use the existing DropdownMenu. Focus rings are the existing focus-visible style.
- Tab order: folder bar → columns, left to right → preview → uploads card.
- `aria-current="true"` for the open folder in its parent column and the previewed file row, and `aria-current="page"` on the last breadcrumb.
- The preview `<aside>` is labelled. Escape closes it, and focus returns to the row.
- The uploads card is `aria-live="polite"`, and its collapse and Details controls use `aria-expanded`.
- Contrast: muted text stays `--text-muted` on dark backgrounds, as elsewhere in the app.
