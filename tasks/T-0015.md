# T-0015 Folder info panel from the folder action menu
Issue: #33
Request: #31
Status: review

## Goal
Give each folder an "Info" panel that shows details about that folder, starting with what was removed from the
heading in T-0014: how many folders and files it directly contains. The human suggested reaching it from the
action menu each folder has (today: Rename, Download, Move, Move to Trash in the folder row menu of
`apps/web/src/components/files/FileList.tsx`; on phone the menu opens by press-and-hold or Shift+F10).

Data at hand: `FolderRecord` has name, fullPath, createdAt, updatedAt; the page has direct file counts per child
folder (`folderFileCounts`); a subfolder count for a child folder may need its folder-children query.
Design decides the panel form (dialog, side panel like the file preview, or popover), its contents and whether
the current folder also gets the entry (e.g. from "Folder options" / "Dockspace options").

## Acceptance criteria
1. Every folder row's action menu (desktop `⋯` / right-click, phone press-and-hold) has an "Info" item (final
   wording from design) that opens the folder info panel for that folder.
2. The panel shows at least: folder name, its path, number of direct subfolders, number of direct files; plus
   any other fields the chosen design includes (e.g. created/modified dates, total size if available).
3. Counts are correct for empty folders, folders with only subfolders, and folders with only files, and use
   singular/plural correctly ("1 file", "2 folders").
4. The panel can be closed with Escape, a visible Close button and (if a dialog) the backdrop; focus moves into
   the panel on open and returns to the opener on close (T-0009 pattern). It has an accessible name and passes axe.
5. Works in the desktop and phone layouts; while counts load, the panel shows a loading state, and an error state
   if the request fails.
6. Unit tests cover the menu item, the counts and the open/close focus behavior. Build, typecheck and tests pass.

### Components
1. **New `apps/web/src/components/files/FolderInfoPanel.tsx`**, modelled on `FilePreviewPanel.tsx` and reusing its
   classes (`dockspace-preview`, `dockspace-preview--side|page`, `__head`, `__icon`, `__title`, `__body`, `__meta`, `__hint`).
   Props (suggested): `dockspaceId`, `folder: { folderNodeId, fullPath, name, createdAt?, updatedAt? }`,
   `locationLabel: string | null` (parent path, see below), `variant: 'side' | 'page'`, `backLabel?`,
   `onOpen?: () => void` (omit for the current folder), `onClose`.
   - Root element: `<aside className="dockspace-preview dockspace-preview--{variant} dockspace-folder-info" aria-label={`Info for ${name}`}>`.
   - Header, left to right: page variant only, back button (`ArrowLeft`, ghost icon button, `aria-label={backLabel}`,
     e.g. "Back to Lisbon 2025"); `Folder` icon (16, stroke 1.5, aria-hidden); title = folder name, `h2` in side,
     `h1` in page (the page replaces the phone listing and its h1, same as the preview); **Open** button
     (`Button variant="secondary" size="sm"`, `FolderOpen` icon 14 + "Open") only when `onOpen` is given;
     side variant only, Close button (`X` 18, ghost icon button, `aria-label="Close folder info"`).
   - Body: small uppercase section label "Folder info" (same type style as the column headers, muted);
     then two count tiles in a 2-column grid; then a `<dl class="dockspace-preview__meta">`; then, side variant
     only, the hint `<kbd>Esc</kbd> closes the info` (`dockspace-preview__hint`).
   - Count tiles (`.dockspace-folder-info__stats` grid 1fr 1fr, gap .6rem; each `.dockspace-folder-info__stat`:
     1px `--border`, radius 8px, background rgba(5,8,15,.62), padding .8rem .85rem): accent-tinted icon
     (`Folder` / `File`, 18), the number (1.7rem, 700) and the caption below (muted, .84rem). Caption is
     `count === 1 ? 'folder' : 'folders'` / `'file' : 'files'` (use `pluralize` from `lib/fileFormat` for the
     full phrase in the accessible text). Mark up as `<ul aria-label="Contents">` with one `<li>` per tile, so it
     reads "2 folders", "6 files", "0 folders", "1 file".
   - Meta list, in this order: **Files size** = `formatFileSize(sum of size of direct file children)` followed by
     a muted " (files directly inside)"; omit the row when the folder has 0 direct files. **Created** and
     **Modified** = `formatModifiedDate(createdAt/updatedAt)`; omit a row whose date is unknown (e.g. the
     dockspace root). **Location** = path of the folder's parent, joined with " / " like the preview
     (e.g. "Personal Drive / Travel / Lisbon 2025" for Day trips, "Personal Drive / Travel" for Lisbon 2025);
     omit for the root. Long values truncate with ellipsis and a `title`, as in the preview meta.
2. **Data**: counts and size come from `useFiles(dockspaceId, folder.folderNodeId)` (same query key as the
   discovery, so it shares the cache; no new endpoint). Folders = items with `childType === 'folder'`, files =
   `childType === 'file'`, size = sum of `size` on file items. Name, location and dates render at once: dates of a
   child folder come from the current folder's listing item (`DirectoryChildRecord.createdAt/updatedAt`); the
   current folder's from its parent's listing (already loaded for the ancestor column / parent chips) or omitted.
   - **Loading** (query pending): tiles show a skeleton block in place of the number (caption stays "folders"/"files"),
     Files size shows a skeleton bar, and below the meta list a `role="status"` line with a small spinner:
     "Counting contents…". Close/Open stay usable.
   - **Error**: the tiles and the Files size row are replaced by `<Alert>`-style `role="alert"` box:
     "Couldn't count what {name} contains." + link-style button **Try again** (calls `refetch`). Name, Created,
     Modified, Location stay. No Esc hint change needed (hint may stay hidden in this state, as in the mockup).
3. **`FileList.tsx` → `FolderRow`**: new optional prop `onShowFolderInfo?: (folderPath: string) => void` (with
   `infoActionLabel`, default "Info"), threaded through like `onRenameFolder`. When present, the row menu shows
   **Info** as the FIRST item, then a `DropdownMenu.Separator`, then the existing items unchanged (Rename,
   Download, separator, Move, separator, Move to Trash). Count Info in `hasMenuActions`. Desktop `⋯`, right-click,
   phone press-and-hold and Shift+F10 / ContextMenu key all reach it (same menu). Phone selection mode keeps folder
   rows inert (no menu), as today. The folder whose info is open gets `aria-current="true"` on its
   `.dockspace-browser__folder-button` and the same highlight as the open/current row (soft accent background +
   2px accent left edge, see `.dockspace-column__row[aria-current]` and the Day trips row in the mockup).
4. **`DockspaceFilesHeaderActions.tsx` → `DockspaceOptionsMenu`**: new optional prop `onShowFolderInfo`. When
   given, **Folder info** is the FIRST item followed by a separator, in both variants:
   - desktop (`bar`, "Dockspace options"): Folder info · — · Trash · Detailed usage
   - phone ("Folder options"): Folder info · — · Select items (when shown) · — · New folder · Upload files ·
     Upload folder · — · Trash · Detailed usage
   It opens the panel for the current folder (root included: title = dockspace name, no Location, no dates if
   unknown). No Open button for the current folder (it is already open).
5. **`DockspaceFilesPage.tsx`**: add folder-info state next to `previewFile` (e.g. `infoFolderPath` or a single
   `detail` union `{ kind: 'file' } | { kind: 'folder' }`). Rules:
   - One detail panel at a time: opening a file preview closes folder info and vice versa; Info on another folder
     swaps the panel content.
   - Desktop: render `FolderInfoPanel variant="side"` in the same spot as the side preview inside `.dockspace-work`;
     include it in `hasSidePreview` so the columns keep the current column scrolled into view.
   - Phone: render `variant="page"` in place of the listing, exactly where the phone preview replaces it; save
     `phoneListScrollYRef` on open and restore it on close; `backLabel = Back to {currentFolderLabel}`.
   - **Open** (child folder only): navigates into that folder through the existing open-folder path (which already
     clears the detail via `changeFolderTrail`), then the panel is gone.
   - Navigating to another folder (breadcrumb, columns, chips, back) closes the panel.
   - If the folder disappears from the current listing (renamed, moved, trashed), the panel closes, like the preview.
   - Escape: extend the existing document keydown handler (dialogs and open menus consume Esc first).

### Focus and accessibility (T-0009 pattern)
- On open, focus moves to the panel's Close button (side) or back button (page). Choosing Info again for the folder
  already shown just moves focus there.
- On close (Esc, Close, phone back), focus returns to the opener, resolved with `resolveOpener` from
  `useDialogDismiss.ts`: the row's `⋯` trigger when opened from `⋯`; the row button (`data-row-path`) when the menu was
  opened from the row (right-click, press-and-hold, Shift+F10: `data-return-focus="row"`); the Dockspace/Folder
  options `⋯` trigger for the current-folder entry. On phone the list remounts first: restore scroll, then focus
  the row via `findRowByPath` (or the options trigger), with `preventScroll`. If the opener no longer exists, fall
  back to `[data-dialog-focus-fallback]` / the current column.
- The panel is non-modal: the list stays usable beside it on desktop; no focus trap.
- Accessible name `Info for {name}`; headings h2 (side) / h1 (page). Loading uses `role="status"`, error `role="alert"`.
  Must pass axe in loaded, loading and error states (both variants).
