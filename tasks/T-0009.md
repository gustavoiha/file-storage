# T-0009 Return focus after closing file and folder dialogs
Issue: #21
Request: #5
Status: review
Origin: T-0007

## Goal
After a dialog opened from a menu (e.g. Rename file) is closed with Escape or Cancel, focus goes to `document.body`, so keyboard and screen-reader users lose their place in the list. Dialogs share `useDialogDismiss` (apps/web/src/components/files/useDialogDismiss.ts). Restore focus to a sensible element when a dialog closes.

## Acceptance criteria
1. Closing the Rename file, Rename folder, Move files, Move folder and Add folder dialogs with Escape, Cancel or a backdrop click returns focus to the element that opened the action: the menu trigger (`Actions for {name}` / Folder options / Upload), or the row when the menu was opened from the row.
2. After a successful submit, focus goes to the renamed/moved item's row if it is still in the current folder, otherwise to the list or the trigger; never to body.
3. Dialog look and actions are unchanged. No new serious or critical axe violations. Web tests cover focus after Escape and after Cancel for at least one dialog opened from a row menu.
