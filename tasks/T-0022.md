# T-0022 Confirmation dialogs keep focus after a failed purge or folder trash
Issue: #48
Request: #5
Origin: T-0020
Status: testing

## Goal
After a failed "Purge file now" (`apps/web/src/components/files/ConfirmPurgeFileDialog.tsx`, trash page) or a failed folder Move to Trash (`apps/web/src/components/files/ConfirmFolderTrashDialog.tsx`, files page), the dialog stays open with its error, but keyboard focus is on `body`: the disabled danger button dropped focus during the submit and nothing takes it back, so there is no visible focus until the user presses Tab. Also, after a failed folder Move to Trash, closing the dialog sends focus to the file list instead of the folder's "Actions" trigger or row: during the submit the folder row is re-rendered as a pending "trashing" row (`pendingFolderTrashPaths` in `DockspaceFilesPage.tsx` / `FileList.tsx`), so the opener element captured on open is gone. The Purge dialog and file Move to Trash (T-0012) already return focus to the opener after a failure. Separately, dialog titles are `h3`, which gives an axe `heading-order` violation on the trash page.

## Acceptance criteria
1. After a failed purge or folder trash, focus moves to a dialog control (Cancel), with a visible focus ring for keyboard users. The error stays announced (`role="alert"`).
2. After a failed folder Move to Trash, Escape, Cancel or backdrop return focus to the folder's "Actions" trigger, or to the folder row when the menu was opened from the row (same rule as T-0009 / T-0012). Never the file list fallback or `body` while the folder row still exists.
3. Successful purge and folder trash keep today's focus handling (T-0021 owns focus after a successful purge on the trash page).
4. Dialog titles do not skip heading levels: axe-core reports no `heading-order` violation with the Purge dialog open on the trash page (e.g. use `h2` for all dialog titles consistently).
5. Unit tests cover focus after a failed submit in both dialogs and focus return after a failed folder trash. Build, typecheck and tests pass.

## Security review (round 1)
No findings. PR #51 changes only frontend focus handling and heading levels (`apps/web`): no backend, CDK, API, auth or dependency changes.
- `useDialogDismiss.ts`: the new `recordOpener` / `findOpener` read `data-row-path` from the DOM and look the row up with `findRowByPath`, which compares attribute values with `===` and does not put the path into a CSS selector, so a folder name cannot inject a selector. The only selectors built are constants (`.dropdown-menu__trigger`, `[data-row-path]`).
- `useFocusAfterFailedSubmit` only calls `.focus()` on the dialog's own Cancel button. The error text is still rendered through the `Alert` component as React text (no `dangerouslySetInnerHTML`).
- `h3` to `h2` title changes render the same text through JSX, so the output is escaped as before.
- No new packages and no changes to `package.json` or `package-lock.json`.

## Code review (round 1)
No findings. Reviewed PR #51 (commit 96fbf4d) against the acceptance criteria and engineering-lessons.
- AC1: `useFocusAfterFailedSubmit` tracks `wasSubmitting` across renders, so it focuses Cancel whichever comes first, the error or `isSubmitting=false` (TrashPage: react-query `isPending` drops before the `mutateAsync` rejection sets the error; DockspaceFilesPage: both batched in one render). It only acts when focus fell to body and Cancel is enabled (effect runs after commit, when `disabled` is already cleared). The `role="alert"` error stays. Cancel has no `outline: none` rule, so it uses the browser's `:focus-visible` ring (not checked in a browser; for testing).
- AC2: `recordOpener` stores the row path for a row or a row's `.dropdown-menu__trigger`; `findOpener` looks the re-rendered row up by path (the pending "Trashing..." row has no `data-row-path`), then its `li`'s trigger, else the row (phone layout, which has no trigger, also lands on the row). Row gone: list fallback as before. Other dialogs' close paths are unchanged when the opener is still connected.
- AC3: success paths and `TrashPage.tsx` are untouched.
- AC4: every `.dockspace-dialog__title` is now `h2`; the class sets size and margin, and no CSS or test targets the dialog `h3`.
- AC5: unit tests cover both arrival orders, focus not stolen, error without submit, close after failure and the h2; page tests cover Cancel focus and Escape/Cancel/backdrop to the new Actions trigger and Shift+F10 to the row, plus a TrashPage failed-purge test.
