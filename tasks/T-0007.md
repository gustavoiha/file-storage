# T-0007 Arrow-key navigation in dropdown menus
Issue: #18
Request: #5
Status: engineering
Origin: T-0005

## Goal
The shared `DropdownMenu` (apps/web/src/components/ui/DropdownMenu.tsx) has `role="menu"` items but only handles Escape. Keyboard and assistive-tech users expect the WAI-ARIA menu keys. Add them so every menu in the app (row menus, Folder/Dockspace options, top nav) works the same.

## Acceptance criteria
1. In an open menu, ArrowDown/ArrowUp move focus to the next/previous enabled item and wrap around; Home/End go to the first/last item.
2. Escape still closes the menu and returns focus to the trigger (or to the row for the phone long-press menu). Tab behaviour stays usable (it either moves out and closes the menu, or keeps working as it does now; the PR states which).
3. Disabled items are skipped. Separators are not focusable.
4. Desktop and phone menus keep their current look and actions. No new serious or critical axe violations. Web tests cover the arrow, Home and End keys.
