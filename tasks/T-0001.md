# T-0001 File navigability: single folder navigation, parent-folder context, side preview pane
Issue: #4
Status: awaiting-human

## Goal
Make navigating files in a generic dockspace easier to follow. Today the folder structure appears in two places: the sidebar directory tree (`DockspaceSidebar`) and the folder/file list in the main panel (`FileList` on `DockspaceFilesPage`). File previews open in a modal (`FileViewerDialog`). The human wants:
1. Only one place that shows the folder structure.
2. The previous (parent) folder stays visible after opening a nested folder.
3. File preview shown in a panel on the right instead of a dialog popup.

## Acceptance criteria
- Generic dockspaces show the folder hierarchy in exactly one place. The sidebar tree and the main-panel folder listing no longer duplicate each other.
- After opening a nested folder, the parent folder's contents (or an equivalent view of the previous level) stay visible next to the current folder, for example as Finder-style columns or a persistent parent pane. Design decides which.
- Selecting or opening a file shows its preview in a right-hand pane inside the page layout, not in a modal. The pane can be closed, and the folder view stays usable while it is open.
- Existing file operations keep working in the new layout: upload (files and folders), add folder, rename, move (multi-select), trash folder or file, download (file and folder).
- Media dockspaces (album-based, `DockspaceMediaPage`) are out of scope unless design says otherwise.
- The layout works at narrow or phone widths (for example, the preview pane takes over the view, with a back control).
- Existing web tests are updated or extended to cover the new navigation and preview behavior.

## Design options (round 1)
Posted on issue #4: https://github.com/gustavoiha/file-storage/issues/4#issuecomment-7015863944

#### Option 1: Finder-style columns with a preview column

**Rationale:** One horizontal strip shows the whole path you opened. Each folder level is its own column, so the parent folder and the folders above it stay visible. The preview is the last column. This is the closest match to "see the previous folder" and to how macOS Finder works. The left sidebar tree goes away, and the columns become the only place that shows folders.

**Desktop (> 920px)**
```
+-------------------------------------------------------------------------------------------+
| Dockspace / Projects / 2026 / Invoices                    [Upload v] [+ Folder] [...]     |
+------------------+------------------+--------------------+--------------------------------+
| Dockspace        | Projects         | 2026               | Preview: march.pdf      [DL][x]|
|  > Projects   *  |  > 2025          |  > Invoices     *  | +----------------------------+ |
|  > Photos        |  > 2026       *  |  [ ] march.pdf  *  | |                            | |
|  [ ] notes.txt   |  [ ] brief.docx  |  [ ] april.pdf     | |      (rendered file)       | |
|  [ ] todo.md     |                  |  [ ] may.pdf       | |                            | |
|                  |                  |                    | +----------------------------+ |
|                  |                  |                    | 1.2 MB - PDF - edited 3 Nov    |
|                  |                  |                    | [Rename] [Move] [Trash]        |
+------------------+------------------+--------------------+--------------------------------+
| Uploads (2)  ######---- march.pdf ...                                   [show/hide tray] |
+-------------------------------------------------------------------------------------------+
  * = highlighted item in that column (opened folder or previewed file)
```
- Columns are fixed at about 240px, and the row scrolls sideways when the path is deep. Opening a folder scrolls its column into view, so the last two levels and the preview are always on screen.
- **Sidebar:** removed for generic dockspaces. Actions (Upload files, Upload folder, Create folder) go in the toolbar, and uploads go to a tray at the bottom of the page that you can collapse.
- **Operations:** every folder or file row keeps the `...` menu it has today (Rename / Download / Move / Move to Trash). Toolbar uploads and Create folder go into the **rightmost folder column**, which is the active folder. Checkboxes for multi-select show in every column, but a selection belongs to one column at a time (selecting in another column clears it). The selection bar (`N files selected - Move - Cancel`) sits above the columns.
- **Closing the preview:** use the `x` in the preview header, press `Esc`, or click the folder column again. The preview column then disappears.

**Mobile / narrow (< 720px):** one column at a time, full width. The header shows `< Projects` (a back button named after the parent) above the current folder name. Tapping a file opens the preview full-screen with `< 2026` to go back. Browser back also works, because the preview and folder are kept in the URL.

**Accessibility:** each column is a `listbox` labelled "Folder: 2026". Up/Down moves within a column, Right opens a folder or file, and Left returns to the parent column. The preview is an `aside` labelled "Preview: march.pdf". Focus moves to its heading when it opens and returns to the file row when it closes. The breadcrumb stays above the columns for screen readers.

#### Option 2: Sidebar tree as the only hierarchy + files list + preview pane (3 panes)

**Rationale:** This keeps today's left sidebar tree, which you already use, and makes it the **only** place folders appear. The main panel lists just the **files** of the selected folder. The tree keeps every parent expanded, so the previous folder is always visible. The preview opens as a third pane on the right, similar to a mail client or VS Code.

**Desktop (> 920px)**
```
+------------------------+--------------------------------------+-----------------------------+
| [Upload v] [+ Folder]  | Projects / 2026 / Invoices    [...]  | march.pdf          [DL] [x] |
|------------------------|--------------------------------------| +-------------------------+ |
| FOLDERS                | [ ] Name            Size   Modified  | |                         | |
| v Dockspace            | [ ] march.pdf    *  1.2 MB  3 Nov    | |    (rendered file)      | |
|   v Projects           | [ ] april.pdf       0.9 MB  2 Nov    | |                         | |
|     > 2025             | [ ] may.pdf         1.0 MB  1 Nov    | +-------------------------+ |
|     v 2026             |                                      | 1.2 MB - PDF               |
|       > Invoices  *... |                                      | [Rename] [Move] [Trash]    |
|   > Photos             |                                      |                             |
|------------------------|                                      |                             |
| UPLOADS (2)            |                                      |                             |
+------------------------+--------------------------------------+-----------------------------+
```
- **Sidebar** (320px, as today): Actions, then the Folders tree, then Uploads. Tree rows get the `...` menu folders have today (Rename / Download / Move / Move to Trash). The current folder is highlighted and its ancestors stay expanded.
- **Main panel:** the current folder's files only, with no folder rows. If a folder has subfolders but no files, it shows "No files here - 3 subfolders in the sidebar".
- **Operations:** uploads and Create folder target the selected tree folder. File multi-select, the selection bar and Move work as today. Folder download/rename/move/trash live in the tree row menu, and file actions live in the file row menu and the preview header.
- **Preview pane:** opens at about 40% width (min 360px) and squeezes the file list rather than covering it. Close it with `x` or `Esc`.

**Mobile / narrow (< 920px):** the tree becomes a **"Folders" drawer** opened from a button next to the breadcrumb. It slides in from the left, and picking a folder closes it. The file list is full width. Tapping a file opens the preview full-screen with a `< Invoices` back control.

**Accessibility:** the tree uses `role="tree"`/`treeitem` with `aria-expanded`. Arrow keys expand, collapse and move, and Enter selects. The drawer traps focus and closes with `Esc`. The preview pane has the same focus handling as Option 1.

#### Option 3: Parent + current dual pane, preview replaces the parent pane

**Rationale:** This is a lighter take on "see the previous folder". The page always shows exactly two levels side by side. A narrow **parent pane** lists the parent folder, with the current folder highlighted, and a wide **current pane** gives the detailed list of folders and files. The sidebar tree goes away. When you open a preview, it takes the space on the right, and the parent pane collapses to a thin rail so the list keeps its width. Compared with Option 1 it scrolls less sideways and shows more detail (size, modified date) per row.

**Desktop (> 920px), browsing**
```
+--------------+--------------------+-------------------------------------------------------+
| ACTIONS      | ^ Projects         | Dockspace / Projects / 2026          [...]            |
| [Upload v]   |   > 2025           | [ ] Name                 Size     Modified            |
| [+ Folder]   |   > 2026        *  | > Invoices               -        4 Nov               |
|              |   [ ] brief.docx   | > Receipts               -        1 Nov               |
| UPLOADS (2)  |                    | [ ] plan.pdf             2.1 MB   30 Oct              |
| ####-- a.pdf |                    | [ ] notes.md             4 KB     29 Oct              |
+--------------+--------------------+-------------------------------------------------------+
```
**Desktop, with preview open**
```
+--------------+--+-----------------------------------+--------------------------------------+
| ACTIONS ...  |^ | Dockspace / Projects / 2026  [...]| plan.pdf                     [DL][x] |
|              |P | > Invoices                        | (rendered file)                      |
|              |r | [ ] plan.pdf               *      |                                      |
|              |o | [ ] notes.md                      | 2.1 MB - [Rename] [Move] [Trash]     |
+--------------+--+-----------------------------------+--------------------------------------+
     (parent pane collapses to a rail labelled with the parent name; click it to expand)
```
- **Sidebar** (narrowed to about 220px): Actions and Uploads only, with no Folders tree.
- **Parent pane:** lists the parent's folders and files. Clicking a sibling folder switches to it, and the `^ Projects` header goes up one level. At the root the parent pane is hidden, and the current pane fills the space.
- **Operations:** all of them stay in the current pane, exactly as `FileList` has them today (row `...` menus, checkboxes, selection bar, Move). The parent pane is for navigation only and has no checkboxes.
- **Closing the preview:** use `x` or `Esc`. The parent pane then expands again.

**Mobile / narrow (< 720px):** the parent pane and sidebar are hidden. The current list gets a sticky `< Projects` row at the top, and the Actions and Uploads move into the `...` menu and a small upload badge. The preview opens full-screen with a back control.

**Accessibility:** the parent pane is a `nav` labelled "Parent folder: Projects", and the rail is a button with `aria-expanded`. The current pane keeps today's list semantics. The preview `aside` has the same focus handling as Option 1.

---

**Common to all three:** the preview reuses `FilePreviewContent`. Its header has the file name, Download, Rename, Move, Move to Trash and Close. The open folder and previewed file go in the URL (`?folder=...&file=...`), so reload or back restores them. Media dockspaces stay unchanged.
