# T-0001 File navigability: single folder view, parent context, side preview
Issue: #5
Status: design
Origin: human issue https://github.com/gustavoiha/file-storage/issues/5

## Goal
Make navigating files in a generic dockspace (route `/$dockspaceId`, `apps/web/src/pages/DockspaceFilesPage.tsx`) feel coherent:
- Today the folder structure appears twice: the folder tree in `DockspaceSidebar` (right-hand sidebar, also hosts upload controls/status) and the folder rows + breadcrumbs in `FileList` (main panel). The human wants exactly one place.
- When a nested folder is open, the human wants to still see the previous (parent) folder's contents, not just a breadcrumb (e.g. a column/Finder-style view; exact layout is a design decision).
- File preview currently opens as a modal `FileViewerDialog` (uses `FilePreviewContent`). The human wants the preview shown in a panel to the right of the file listing instead of a popup.

Out of scope: the media dockspace page (`DockspaceMediaPage`, album-based, uses `FileViewerDialog` variant `media-fullscreen`), trash and usage pages, backend changes.

## Acceptance criteria
1. On the generic dockspace files page, the folder hierarchy is rendered in exactly one place; no second folder tree / folder list duplicates it. Upload controls and upload progress/skipped/error status that live in `DockspaceSidebar` today remain reachable and functional.
2. When a folder at depth >= 1 is open, the contents (at least the folder entries) of its parent folder are visible on screen at the same time as the open folder's contents, with the open folder visually marked as selected in the parent. Clicking another folder in the parent switches to it.
3. The user can always navigate back to the dockspace root and to any ancestor in one click.
4. Clicking/opening a file shows its preview (the same content types `FilePreviewContent` supports today: images, video, audio, PDF, text, fallback) in a panel to the right of the listing, not in a modal overlay; the listing stays visible and interactive. The panel shows the file name, a download action and a close control; Escape closes it. Opening another file replaces the preview.
5. Existing file/folder actions keep working from the new layout: multi-select + move, rename, move to trash, download (file and folder), folder rename/move/trash, add folder, upload files/folder, empty-folder state.
6. Navigating to a different folder closes or updates the preview so it never shows a file that is not in the visible listing context (design decides which).
7. At phone width (<= 480px) the layout remains usable with no horizontal page scroll: e.g. preview takes the full width with a back control, and parent context collapses gracefully.
8. The media dockspace page's fullscreen viewer is unchanged.
9. Existing web tests pass; tests added/updated for the single navigation location, parent-folder visibility and side-panel preview.

## Design options (round 1)
Comment: https://github.com/gustavoiha/file-storage/issues/5#issuecomment-7020984032
Mockup HTML: /Users/gustavoiha/Personal/file-storage/.agent-local/design/T-0001/round-1/option-k-{desktop,phone}.html (generator: round-1/src/gen.mjs)
Shared by all options: preview panel on the right with the file name, Download, close (X) and details. Esc closes it, and opening another file replaces it. It uses FilePreviewContent. Sizes are formatted (2.9 MB).

1. **Columns (Finder-style).** Miller columns replace both the sidebar tree and the folder rows. Each open folder is a column, the selected folder is highlighted in its parent column, and the preview is the last column. A breadcrumb bar above links every ancestor. New folder and Upload move to the top bar, and the uploads status shows in a floating card at the bottom left. On phone: one folder at a time with a back button named after the parent and wrapping chips for the parent's folders. The preview opens full width with back. Navigating to another folder closes the preview.
   - https://raw.githubusercontent.com/gustavoiha/file-storage/agent-memory/design/T-0001/round-1/option-1-desktop.png
   - https://raw.githubusercontent.com/gustavoiha/file-storage/agent-memory/design/T-0001/round-1/option-1-phone.png
2. **The tree is the one place.** The left sidebar tree is the only folder navigation, and the main panel lists files only, without folder rows or breadcrumbs. The sidebar keeps Actions and Uploads as today. Folder actions move to a ⋯ menu on tree rows. On phone: a "Travel / Lisbon 2025 ▾" button opens a bottom sheet with the tree plus Upload and New folder. The preview opens full width with back. Choosing another folder closes the preview.
   - https://raw.githubusercontent.com/gustavoiha/file-storage/agent-memory/design/T-0001/round-1/option-2-desktop.png
   - https://raw.githubusercontent.com/gustavoiha/file-storage/agent-memory/design/T-0001/round-1/option-2-phone.png
3. **Outline list.** There is no sidebar. One list starts at root, and folders expand in place, indented, with size and date columns. Ancestor rows stay pinned while scrolling. The last folder opened is current and is the target for New folder and Upload. Uploads show as a status strip under the header. On phone: the same outline, with the preview as a bottom sheet over about 80% of the screen. The preview stays open while its folder is expanded.
