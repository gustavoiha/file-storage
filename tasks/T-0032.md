# T-0032 Gallery preview returns focus to its tile on close
Issue: #70
Request: #65
Origin: T-0029
Status: review

## Goal
In the media gallery, closing the full-screen preview (Escape, the close button, Close, or the backdrop) leaves keyboard focus on `<body>`, so a keyboard or screen reader user loses their place. Focus should go back to the tile that opened the preview, or to the tile of the item shown last after previous/next. Already on main: `apps/web/src/components/files/FileViewerDialog.tsx` (variant `media-fullscreen`, used by `DockspaceMediaPage`) has no code that returns focus on close. Found while testing T-0029 (#66), round 1, finding 2.

Notes: the gallery is virtualized (`VirtualizedMediaGrid.tsx`), so the tile may not be rendered when the preview closes. Follow the engineering-lessons focus rule: end the fallback chain with an always-mounted element (the scroll box has `tabIndex={-1}` after T-0029). Build on main after T-0029 (PR #68) is merged, and coordinate with T-0030 (gallery layout).

## Acceptance criteria
1. On All media and in an album view, open the preview from a tile with the keyboard (Enter), then close it with Escape, the close control, Close, or a backdrop click: focus goes to the tile that opened it, with the visible `:focus-visible` ring for keyboard users.
2. After moving through items with Next/Previous (buttons or arrow keys) and then closing, focus goes to the tile of the item shown last. If that tile is outside the rendered (virtualized) window, the grid scrolls it into view and focuses it. If it cannot be rendered, focus goes to an always-mounted element (for example the grid scroll box). Focus never stays on `<body>`.
3. Opening with a mouse click and closing does not show a focus ring on the tile (`:focus-visible` only).
4. Preview, previous/next, multi-select, grid size toggle and infinite scroll keep working as before.
5. Unit tests cover each close path and the after-previous/next case, including the tile outside the render window. Build, typecheck and tests pass.

- PR: https://github.com/gustavoiha/file-storage/pull/72 (branch `agent/T-0032-gallery-preview-focus-return`, from main at c5dfcdf).
- `closePreview` in `useDockspaceMediaController` remembers the item shown last and, before the preview unmounts, calls the grid's new `focusItem(fileNodeId)` (`VirtualizedMediaGrid` `focusHandleRef`). This covers every close path (Escape, Close preview, backdrop, the empty area around the media). The fallback chain is: the rendered tile, else the tile scrolled into the middle of the scroll box and focused after that render, else the scroll box (item gone or not renderable). With no grid rendered, focus goes to the Select multiple toggle.
- `FileViewerDialog`: a press on the backdrop or the empty dialog area now calls `preventDefault()` on mousedown. In Chromium, the default action of a press on a non-focusable element blurred the tile right after it was focused, so focus ended on `<body>`.
- No CSS changes; the ring is the existing `:focus-visible` one.
- Tests: new `DockspaceMediaPreviewFocus.test.tsx` (13 tests, real dialog) for each close path, Next/Previous by button and by arrow key, a tile past the rendered rows, the grid scrolled away while the preview was open, the item removed (scroll box), no grid (Select multiple), the album view, and multi-select after a close. 11 of them fail without the fix. Typecheck, tests and build pass.
- Checked in headless Chromium with a mocked API (desktop and phone): keyboard closes land on the tile with `:focus-visible` (including 120 x ArrowRight to tile 128, scrolled into view, and the album view); mouse and touch closes land on the tile with no ring.
- Pre-existing, not changed (for the PM): while the preview is open, focus stays on the tile behind the overlay. Tab walks the hidden grid, so keyboard users cannot reach Close preview or Next/Previous with Tab (no focus move into the preview, no focus trap). Escape and the arrow keys work.
