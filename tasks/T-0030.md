# T-0030 Gallery layout: no card frame, actions in a menu, gapless grid
Issue: #67
Request: #65
Status: design

## Goal
Make the media gallery page use its space for the media. Today the main panel is a card (`.media-workspace__main` in `apps/web/src/styles/layout.css`: border, 10px radius, padding, own background), the always-visible 320px sidebar (`DockspaceMediaWorkspace.tsx`: Actions = Find duplicates / Browse media, Trash, Detailed usage; Albums = All media + each album with its count; Uploads = active uploads with retry and skipped duplicates with Dismiss) takes a column on desktop and stacks under the gallery on phone, and the grid has a 12px gap (`MEDIA_GRID_GAP_PX`) with 12px rounded, bordered tiles (`.media-card`). The human wants no card frame, the sidebar replaced by a menu, and tiles rendered without gaps or rounded borders. Where albums, uploads and the actions live once the sidebar is gone is a layout decision, so this goes to design first.

## Acceptance criteria
1. The gallery main area has no card frame: no border, radius, inner padding or separate panel background around the grid; the grid spans the full content width (edge to edge on phone).
2. The sidebar is not always visible on desktop or phone. Its contents are reachable from a menu (exact form per the chosen design), and everything stays reachable: Find duplicates / Browse media, Trash, Detailed usage, switching between All media and each album (with counts and the current one marked), and the uploads list (progress, retry, skipped duplicates with Dismiss). Active uploads stay noticeable while the menu is closed (e.g. a count or progress on the toolbar).
3. Grid tiles are square with no gap between them, no rounded corners and no border. Selected tiles and keyboard focus stay clearly visible (inset ring or overlay, not a border that reintroduces a gap); hover does not move the tile.
4. Unchanged: grid size toggle, upload button, multi-select with bulk Add to album / Trash selected / Cancel, preview with previous/next, the duplicates view, and T-0029's loading and scroll behaviour.
5. Accessibility: the menu opens and closes by keyboard (Escape closes and returns focus to its trigger), has an accessible name, and the page has no new axe violations on desktop and phone.
6. Unit tests updated for the new structure. Build, typecheck and tests pass.

## Design options (round 1)
Comment: https://github.com/gustavoiha/file-storage/issues/67#issuecomment-7078721186
Mockups: `$LOCAL/design/T-0030/round-1/option-{1,2,3}-{desktop,phone}.html` (generator `src/gen.mjs`).
Shared by all options: no card frame (toolbar is a plain strip, grid edge to edge on desktop and phone); square tiles with no gap, radius or border; hover, focus and selection drawn inside the tile (tint, inset ring, check), no lift. Square tiles need the row height to follow the column width (today `rowHeightPx` is fixed). T-0029's loading and scrolling are kept, and selection mode is unchanged.

### Option 1: Album menu, ⋯ options, floating uploads card
The current album name is a menu button on the left of the toolbar (role=menu "Albums", menuitemradio with aria-checked on the current one). Find duplicates / Trash / Detailed usage go in a `⋯` "Gallery options" menu. Uploads use the files page's floating UploadsCard (bottom right, collapses to a pill "Uploading 3 of 4 · 26%" with a red failure dot). Phone: the album button fills the toolbar and opens a full-screen album list; the uploads pill sits bottom left next to the Upload FAB.
- Desktop: https://raw.githubusercontent.com/gustavoiha/file-storage/agent-memory/design/T-0030/round-1/option-1-desktop.png
- Phone: https://raw.githubusercontent.com/gustavoiha/file-storage/agent-memory/design/T-0030/round-1/option-1-phone.png

### Option 2: One Gallery menu (the sidebar folded into a panel)
A single Menu button (disclosure) opens a panel over the grid with Albums, Actions and Uploads in a fixed order (nav "Gallery menu"); on phone it is a full page with a back arrow. With the menu closed: the album name is the toolbar title, and uploads show as a badge on Menu (active count, red on failure), a progress chip that opens the menu at Uploads, and a 2px progress line under the toolbar.
- Desktop: https://raw.githubusercontent.com/gustavoiha/file-storage/agent-memory/design/T-0030/round-1/option-2-desktop.png
- Phone: https://raw.githubusercontent.com/gustavoiha/file-storage/agent-memory/design/T-0030/round-1/option-2-phone.png

### Option 3: Album tabs, uploads beside the Upload button, ⋯ actions
Albums as tabs in the toolbar (as many as fit, then "More (n)" with a filter, like the T-0026 dockspace tabs). A progress button "3 of 4 · 26%" next to Upload, shown only while uploads exist, opens an uploads popover (a full page on phone). Actions go in `⋯`. Phone: a row of album chips that scrolls sideways under the toolbar; the progress pill sits next to the Upload FAB. Trade-off: albums stay visible, and phone gets one extra row.
