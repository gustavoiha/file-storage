# T-0045 Collapsed uploads pill: skipped files are not reported as a failed upload
Issue: #96
Request: #65
Origin: T-0039
Status: testing

## Goal
On phone the uploads card starts collapsed. When files are only skipped (for example a non-media file picked in the gallery), the collapsed pill shows the red failure dot and its accessible name is "Expand uploads: Uploads, an upload failed", although nothing failed and the accepted files uploaded. `apps/web/src/components/files/UploadsCard.tsx` treats any `uploadErrorMessage` as a failure (`hasFailure`). The card is shared by the gallery and the files page. Found while testing T-0039 (#83), round 1, finding 1 (pre-existing from T-0030, already on main).

## Acceptance criteria
1. When the card only holds a skipped-files notice (no upload has status failed), the collapsed pill does not say "an upload failed" and does not show the red failure dot; it says something neutral and accurate, for example "Expand uploads: Uploads, files were skipped" (wording may be refined).
2. A real failed upload still shows the red dot and "an upload failed", on both the gallery and the files page. Real selection errors that the files page shows in the card are still shown as errors (check each caller of `uploadErrorMessage` and keep error vs notice correct).
3. The expanded card still shows the skipped message in the same place.
4. Unit tests cover the collapsed pill for skipped-only and for failed uploads. Build, typecheck and tests pass.
