# T-0026 Quick dockspace switcher panel (Slack-style)
Issue: #58
Request: #57
Status: review

## Goal
Today the only way to change dockspace is to go back to `/dockspaces` (top nav "Dockspace" brand link) and pick a card from the grid (`apps/web/src/pages/DockspacesPage.tsx`, `components/files/DockspaceList.tsx`). The human finds this uncomfortable and wants to experiment with a Slack-like embedded panel that lets the user toggle between dockspaces without leaving the dockspace they are in. Add a persistent dockspace switcher on the dockspace pages so switching takes one action from anywhere inside a dockspace.

Code pointers: routes in `apps/web/src/router/router.tsx` (`/dockspaces/$dockspaceId`, `/trash`, `/usage` under `AuthenticatedLayout`, `TopNav` in the root shell); `DockspaceWorkspacePage.tsx` picks the files page or the media page (`PHOTOS_VIDEOS`); the dockspace list comes from `useDockspaces()` (React Query, already cached); phone layout is `PHONE_LAYOUT_QUERY` (max-width 900px).

## Acceptance criteria
1. Desktop (wider than 900px): on every page inside a dockspace (files, Photos & Videos media page, trash, usage) a switcher panel is visible without opening anything. It lists all of the user's dockspaces, each identifiable by name (or a recognisable short form with the full name available on hover/focus and as its accessible name) and by type (Generic Files vs Photos & Videos), with the current dockspace clearly marked.
2. Choosing another dockspace in the switcher opens it with one click, at its root, without passing through `/dockspaces`. Nothing from the previous dockspace carries over (open folder, preview, folder info panel, selection, status messages). Works for both dockspace types.
3. Phone (900px and narrower): the switcher is reachable with one tap from any dockspace page (it may be collapsed into a drawer/sheet or similar) and switching takes at most two taps; the switcher closes after a switch, and closing it without switching returns focus to the control that opened it. The files page layout does not get a horizontal scroll at 390px wide.
4. The switcher offers a way to create a new dockspace (inline or by going to the existing create form); after creating one it appears in the switcher without a reload.
5. States: while the dockspace list loads the switcher shows a loading placeholder; on a failed load it shows an error with Try again; with many dockspaces (e.g. 30) the list scrolls inside the panel and the current one stays reachable; long names are truncated visually but not in the accessible name.
6. Accessibility: the switcher is a navigation landmark labelled "Dockspaces" (or equivalent), every item is keyboard reachable with a visible focus ring (`:focus-visible`), the current item has `aria-current="page"`, icon-only controls have accessible names, and axe reports no new violations on the files, media, trash and usage pages.
7. The `/dockspaces` page (list + create form) and the top nav keep working; existing files-page behaviour (columns, preview, info panel, focus management from T-0009..T-0024) is unchanged apart from the space the panel takes.
8. Unit tests cover the switcher (list, current marker, switching, loading/error, phone open/close focus). Build, typecheck and tests pass.

## Notes
- The human framed this as an experiment: design should propose 3 options (e.g. a narrow icon rail like Slack's, a labelled collapsible sidebar, a header dropdown/popover combined with a rail) and say how each behaves on phone.
- Frontend only: the dockspace list API already returns everything needed (name, type). Keyboard shortcuts for switching (e.g. Ctrl/Cmd+1..9) are optional; design may propose them.

### Where it shows
- Only on routes inside a dockspace: `/dockspaces/$dockspaceId` (files page and Photos & Videos media page), `/dockspaces/$dockspaceId/trash`, `/dockspaces/$dockspaceId/usage`. The `/dockspaces` list page, `/settings/password` and auth pages keep today's top nav (brand + Account) unchanged.
- Data: `useDockspaces()` (already cached). Order = the order the API returns (same as the `/dockspaces` grid). If the URL's dockspace is not in the list, show the tabs with none marked current.
- New component `apps/web/src/components/ui/DockspaceSwitcher.tsx` (desktop tab strip + phone bar/full-screen list), rendered by `TopNav` (desktop strip between the brand and Account) and, on phone, as a bar directly under the top nav. Use `PHONE_LAYOUT_QUERY` (max-width 900px) to pick the variant; render only one of the two.
- Styles in `layout.css` (`.dockspace-tabs*`, `.dockspace-switcher-bar*`, `.dockspace-switcher-screen*`), using the existing tokens (`--bg`, `--bg-soft`, `--bg-elevated`, `--border`, `--text`, `--text-muted`, `--accent`).

### Desktop (wider than 900px)
- Top nav (height stays `--app-top-nav-height`, 3.75rem): `DOCKSPACE` brand link (still to `/dockspaces`) · `<nav aria-label="Dockspaces">` taking the remaining width · Account menu (unchanged).
- Inside the nav, in order: a `<ul>` of tabs, the "More (n) ▾" button (only when some tabs are hidden), the "+" button.
- Tab = `<a>` (TanStack `Link` to `/dockspaces/$dockspaceId`), 2.6rem tall, bottom-aligned in the nav, padding 0 .85rem, max-width 220px, min-width 96px, gap .45rem, 0.88rem/500 text in `#cfcfd8`. Content: type icon 15px (`FolderOpen` muted for Generic Files, `Film` in `#ff9f8a` for Photos & Videos, same icons as `DockspaceList`) + name with ellipsis. Hover: `rgba(255,255,255,.04)` background, radius 10px 10px 0 0.
- Current tab (`aria-current="page"`, on files, media, trash and usage pages): 700 weight, `--text` colour, 1px `--border` on top/left/right with no bottom border, background equal to the surface directly below the nav so it joins the page, a 2px `--accent` bar along its top edge (inset 10px each side), icon `#9bcfff`.
- Accessible name of each tab: full name + type, e.g. "Camera Roll, Photos & Videos" (visible name + `.visually-hidden` ", Photos & Videos"). Tooltip: on hover (after ~400ms) and immediately on `:focus-visible`, a small tooltip below the tab with the full name (bold) and the type (muted), `--bg-elevated` card with `--border`; `aria-hidden="true"` since the name already carries it. Shown for every tab (needed for truncated ones; harmless for the rest).
- Overflow: measure with a `ResizeObserver` on the nav. Show as many tabs as fit in list order; the rest go into "More (n)". The current dockspace is always visible: if it would be hidden, it takes the place of the last visible tab and that one moves into More. With nothing hidden, no More button. Recompute on resize and when the list changes.
- "More (n) ▾": `ui-button--secondary ui-button--sm`, `aria-expanded`, `aria-controls` the popover. Popover: non-modal disclosure panel (not `role="menu"`, it contains an input), 340px wide, anchored under the button, right-aligned, `--bg-elevated`, `--border`, radius 10px, shadow. Rendered inside the Dockspaces `<nav>` so its links are in the landmark. Contents: labelled search input "Filter dockspaces" (filters by name, case-insensitive; "No dockspaces match" when empty), a `<ul>` of the hidden dockspaces (row: type icon, name with ellipsis, type label right-aligned in muted 0.72rem, link to the dockspace root), a separator, then "All dockspaces" (grid icon) link to `/dockspaces`. The list scrolls inside the popover (max-height about 60vh) with 30 dockspaces.
- Popover keyboard: opening moves focus to the filter input; ArrowDown/ArrowUp move between the rows and "All dockspaces"; Enter follows the link; Esc closes and returns focus to More; Tab past the last item or a click outside closes it (focus stays where it went). Choosing a row closes it.
- "+" button: 2rem square icon button, `aria-label="New dockspace"`, opens the existing `DropdownMenu` (role menu) with a "NEW DOCKSPACE" label and two items: "Generic Files" (`FolderOpen`) and "Photos & Videos" (`Film`). Each opens the existing create dialog for that type (extract the dialog from `CreateDockspaceForm` into a reusable piece so both `/dockspaces` and the switcher use the same dialog, title, description, button copy and validation). On success: the list query is invalidated (already done by `useCreateDockspace`), then navigate to the new dockspace's root (the API returns the created dockspace) and move focus to its now-current tab. Cancel or Esc returns focus to "+". The `/dockspaces` page keeps its current behaviour (no navigation after create).
- Clicking another tab (or a More row) navigates to that dockspace's root with no state carried over. The files page keeps folder trail, preview, folder info panel, selection, dialogs and status messages in component state, so key the workspace page by `dockspaceId` (e.g. `<DockspaceFilesPage key={dockspaceId} />` / media page likewise) so everything resets. Works for both types (`DockspaceWorkspacePage` already picks files vs media).
- Clicking the current tab: from trash or usage it goes back to that dockspace's root; on the files/media page it is the same URL and changes nothing (no reset of the open folder).
- Loading (no cached list yet): in place of the tabs, three skeleton pills (120/100/110px, 1.4rem tall) in a `role="status"` element labelled "Loading dockspaces"; More and + hidden.
- Error: in place of the tabs, a compact inline alert that fits the nav height: alert icon, "Couldn't load dockspaces." and a "Try again" text button that calls `refetch()`. + stays available.
- Columns keep their full width; only the top nav changes. No horizontal scroll at 901px (tabs collapse into More; at very narrow widths More can hold every tab except the current one).

### Phone (900px and narrower)
- No tabs in the top nav (brand + Account icon menu as today). Directly under the top nav, on every in-dockspace page, a full-width bar (padding .55rem .75rem, bottom border, background `rgba(13,15,20,.9)`) with one button: type icon (16px), current dockspace name (700, ellipsis, takes the remaining width), muted "N dockspaces" (0.75rem), chevron-down. Button: `--bg-soft`, `--border`, radius 10px, min-height 2.75rem. `aria-haspopup="dialog"`, `aria-expanded`, accessible name "Switch dockspace, current: Personal Drive, Generic Files". It must not cause horizontal scroll at 390px (`min-width: 0` on the flex children).
- One tap opens a full-screen dialog (`role="dialog"`, `aria-modal="true"`, `aria-labelledby` its `<h2>Dockspaces</h2>`), covering the viewport including the top nav, like the phone file preview. Header: back arrow icon button `aria-label="Close dockspaces"`, title "Dockspaces", "+" icon button (`aria-label="New dockspace"`, same create menu and dialog as desktop). Below: labelled "Filter dockspaces" input. Then `<nav aria-label="Dockspaces">` with ALL dockspaces in list order, each a link row min-height 3.5rem: type icon 20px (`#9bcfff` Generic, `#ff9f8a` media), name (700, single line, ellipsis) over the type (muted 0.8rem; current row adds " · Current"), chevron-right. Current row: `aria-current="page"` and a 3px inset `--accent` bar on the left. At the end: centred "All dockspaces" link to `/dockspaces`.
- Opening focuses the current dockspace row (not the filter, to avoid popping the keyboard) and scrolls it into view; page scroll is locked while open; with 30 dockspaces the list scrolls inside the dialog.
- Tapping a row navigates to that dockspace's root and closes the dialog; focus then goes to the switcher bar button (now showing the new name). Tapping the current row just closes it (same rules as the desktop current tab). Back arrow or Esc closes without switching and returns focus to the bar button. Switching = 2 taps (bar, row).
- Loading: the bar shows a full-width skeleton of the button's size inside `role="status"` "Loading dockspaces". Error: the bar shows an inline alert "Couldn't load dockspaces." with a "Try again" `ui-button--secondary ui-button--sm` (`refetch()`).

### Accessibility summary
- One `<nav aria-label="Dockspaces">` landmark (desktop strip; on phone the list inside the dialog). Links, not ARIA tabs. `aria-current="page"` on the current item. All controls keyboard reachable in DOM order, visible `:focus-visible` ring (existing focus ring style). Icon-only controls named: "New dockspace", "Close dockspaces". More has `aria-expanded`/`aria-controls`; the phone bar has `aria-haspopup="dialog"`/`aria-expanded`. Truncated names keep the full name in the accessible name. axe: no new violations on files, media, trash and usage.
- Keyboard shortcuts for switching are not part of this design.
