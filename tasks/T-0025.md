# T-0025 Failed folder listing stays steady during uploads and folder creates
Issue: #56
Request: #31
Origin: T-0024
Status: engineering

## Goal
On the dockspace files page, when the open folder's listing has failed (error with Try again shown, T-0024), an upload or folder create into that folder should not disturb the error state or lose the new item:
- The refetch that follows the upload or create (and any other background refetch not started from Try again) removes the error and Try again for a moment and re-adds it (screen readers may announce it again), and focus on Try again moves to the list. React Query clears `error` while a query with no data refetches, and `listingFailed` in `apps/web/src/pages/DockspaceFilesPage.tsx` only stays true during a Try again retry (`isRetryingListing`).
- A folder created into the failed folder stays "Creating..." until the listing loads, and an uploaded file disappears from the list once its upload finishes, because pending rows are cleared against a fetched listing that is missing. Pre-existing on main.

## Acceptance criteria
1. While the open folder's listing is unknown and its last request failed, any background refetch (after an upload, a folder create, discovery) keeps the error with Try again mounted, does not re-insert the alert, and leaves focus on Try again if it was there. Same on desktop and phone.
2. A folder created into a failed folder no longer stays "Creating..." indefinitely, and a file uploaded into it does not silently disappear: either the item stays visible as created/uploaded until the listing loads, or the page tells the user the item was saved and the listing will show it after Try again.
3. Try again, the empty state for a truly empty folder, and the T-0024 behaviour (no empty state while the listing failed) are unchanged.
4. Unit tests cover the background refetch keeping the alert and focus, and the create/upload into a failed folder. Build, typecheck and tests pass.
