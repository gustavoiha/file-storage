# T-0002 Show file sizes in folder listings (folder-children API returns size)
Issue: #5
Status: new
Origin: T-0001

## Goal
The folder-children endpoint (`packages/backend/src/handlers/listFolderChildren.ts`) returns file entries without a size. Because of this, the web listing (the columns view from T-0001: current and ancestor columns on desktop, and rows on phone) hides the Size column, and only the preview shows the size, which it gets from the download session. Return the size of each file from the API and show it in the listings.

## Acceptance criteria
1. The folder-children response includes each file's size in bytes, taken from the stored file metadata. Existing items that have no stored size are handled gracefully, with no error and no size shown.
2. The web app shows the formatted size (e.g. "2.9 MB") in the current column, in ancestor columns and in phone rows, and the "Size" column header is shown on desktop when sizes are present.
3. The preview details can use the listing size instead of depending on the download session for it.
4. Backend tests cover the size field, web tests cover the size rendering, and typecheck, test and build pass.
