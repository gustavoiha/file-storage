# T-0028 Show a load error on the dockspaces and usage pages when the dockspace list fails
Issue: #63
Request: #57
Origin: T-0027
Status: filtering

## Goal
When `GET /dockspaces` fails with anything other than 403 (e.g. 500 or a network error), two pages hide the failure. `/dockspaces` shows "Your Dockspaces" with only the create cards, as if the account had no dockspaces, which invites creating duplicates (`apps/web/src/pages/DockspacesPage.tsx` only handles 403 and renders `dockspaces.data ?? []`). `/dockspaces/<id>/usage` says "Dockspace not found." (`apps/web/src/pages/DockspaceUsagePage.tsx` only handles 403 and loading). Both should show a load error with Try again, following the existing failed-listing pattern (T-0024, T-0027). Pre-existing on main; found while testing T-0027 (findings 1 and 2, screenshots `d-list-500-error.png`, `d-usage-500-error.png` in `$LOCAL/logs/T-0027/`).

## Acceptance criteria
1. With `GET /dockspaces` failing (500 or network error), `/dockspaces` shows an error (e.g. "Couldn't load dockspaces.") with Try again instead of the dockspace grid and create cards; no empty-looking list.
2. With the list failing, the usage page shows a load error with Try again, not "Dockspace not found."; "Dockspace not found." stays for a list that loaded without that dockspace.
3. Try again refetches once per press (busy state with `aria-disabled`/`aria-busy`, focus kept on it after a failed retry); on success the normal page shows. The request count stays bounded (no loop), and the error stays mounted during a refetch.
4. 403 still shows the Not Authorized notice; normal loading still shows the loader and then the page.
5. Unit tests cover the failing list on both pages. Build, typecheck and tests pass.

## Review decisions (round 1)
- **C1 — critical.** Confirmed in PR #64. If Try again succeeds while the retry button has focus and the page then has no focus target, focus stays on `<body>`. This happens on the usage page when the loaded list does not contain the dockspace ("Dockspace not found." has no control, so `backLinkRef.current` is null), and on either page when the retry returns 403 (the Not Authorized card has no control). This breaks the engineering-lessons focus rule, which says never to let focus fall to `<body>` and to fall back to a `tabIndex={-1}` element with a `:focus-visible` ring. The fix is small: when `getFocusTarget()` returns nothing, focus a `tabIndex={-1}` fallback (e.g. the page `<h1>`, with `Page` taking a ref or `tabIndex` for its title, or the "Dockspace not found." paragraph and the Not Authorized card title), add a `:focus-visible` ring, and add tests for a usage page retry that loads a list without the dockspace and a retry that returns 403.
