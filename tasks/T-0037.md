# T-0037 Gallery preview arrow keys seek video/audio instead of changing the item
Issue: #81
Request: #65
Origin: T-0035
Status: review

## Goal
In the media gallery's full-screen preview, the document-level ArrowLeft/ArrowRight handler in `apps/web/src/components/files/FileViewerDialog.tsx` (variant `media-fullscreen`) calls `preventDefault()` and switches to the previous/next item even when the key press comes from a `<video controls>` or `<audio controls>` element. That suppresses the media's native keyboard seek, so a keyboard user who tabs to the video (an intended Tab stop since T-0035) cannot seek with the arrow keys; each press changes the item instead. Already on main. Found in review of T-0035 (#77), code review round 1, finding C2.

Notes: skip gallery navigation when `event.target` is (or is inside) an `audio`, `video`, `input`, `textarea`, `select` or `iframe`. Build after T-0035 (PR #80) is merged; it changes the same file.

## Acceptance criteria
1. With focus on the preview's video or audio controls, ArrowLeft/ArrowRight seek the media (the browser's default) and do not change the shown item.
2. With focus on Close preview, Previous, Next or nothing in particular, ArrowLeft/ArrowRight still change the item as today; Escape still closes the preview from anywhere in it.
3. Focus behaviour from T-0032 and T-0035 (focus on open, Tab trap, focus return on close) is unchanged.
4. Unit tests cover arrow keys from a media element (no navigation, default not prevented) and from the other controls (navigation). Build, typecheck and tests pass.
