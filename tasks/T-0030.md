# T-0030 Gallery layout: no card frame, actions in a menu, gapless grid
Issue: #67
Request: #65
Status: review

## Goal
Make the media gallery page use its space for the media. Today the main panel is a card (`.media-workspace__main` in `apps/web/src/styles/layout.css`: border, 10px radius, padding, own background), the always-visible 320px sidebar (`DockspaceMediaWorkspace.tsx`: Actions = Find duplicates / Browse media, Trash, Detailed usage; Albums = All media + each album with its count; Uploads = active uploads with retry and skipped duplicates with Dismiss) takes a column on desktop and stacks under the gallery on phone, and the grid has a 12px gap (`MEDIA_GRID_GAP_PX`) with 12px rounded, bordered tiles (`.media-card`). The human wants no card frame, the sidebar replaced by a menu, and tiles rendered without gaps or rounded borders. Where albums, uploads and the actions live once the sidebar is gone is a layout decision, so this goes to design first.

## Acceptance criteria
1. The gallery main area has no card frame: no border, radius, inner padding or separate panel background around the grid; the grid spans the full content width (edge to edge on phone).
2. The sidebar is not always visible on desktop or phone. Its contents are reachable from a menu (exact form per the chosen design), and everything stays reachable: Find duplicates / Browse media, Trash, Detailed usage, switching between All media and each album (with counts and the current one marked), and the uploads list (progress, retry, skipped duplicates with Dismiss). Active uploads stay noticeable while the menu is closed (e.g. a count or progress on the toolbar).
3. Grid tiles are square with no gap between them, no rounded corners and no border. Selected tiles and keyboard focus stay clearly visible (inset ring or overlay, not a border that reintroduces a gap); hover does not move the tile.
4. Unchanged: grid size toggle, upload button, multi-select with bulk Add to album / Trash selected / Cancel, preview with previous/next, the duplicates view, and T-0029's loading and scroll behaviour.
5. Accessibility: the menu opens and closes by keyboard (Escape closes and returns focus to its trigger), has an accessible name, and the page has no new axe violations on desktop and phone.
6. Unit tests updated for the new structure. Build, typecheck and tests pass.

### 1. Page frame (layout.css, `DockspaceMediaWorkspace.tsx`)
- Remove the sidebar `<aside class="dockspace-sidebar media-workspace__sidebar">` and the two-column `dockspace-page-shell media-workspace-shell` wrapper: one column only. Delete CSS that only the sidebar used (`.media-workspace__uploads`, `.media-sidebar__*`), not the shared `dockspace-sidebar__*` rules the files page still uses.
- `.media-workspace__main`: no border, radius, padding or background; `gap: 0`. The workspace is a full-height column (toolbar, then the grid scroll box with `flex: 1; min-height: 320px` in place of `height: min(68vh, 760px)`), so no empty band shows under the grid. Keep every T-0029 scroll rule (`overflow-anchor: none`, `overscroll-behavior: contain`, reserved footer).
- Toolbar (`.media-workspace__main-controls`): a plain strip, `padding: 0.55rem 1rem` (phone `0.5rem 0.75rem`), `min-height: 3.35rem`, `border-bottom: 1px solid var(--border)`, `background: rgba(0, 0, 0, 0.35)`, single row, `gap: 0.5rem`; right group `margin-left: auto; gap: 0.4rem`. No wrapping on desktop.
- Alerts above the toolbar keep showing, with `0 1rem` side margin. The `uploadErrorMessage` Alert is removed: that message goes into the uploads card (as on the files page).
- The grid runs edge to edge (no side padding) on desktop and phone. The duplicates view and the empty/loading texts keep `padding: 1rem` so their text does not touch the edge.

### 2. Toolbar contents

### 3. Album menu (new `apps/web/src/pages/dockspaceMedia/GalleryAlbumMenu.tsx`)
Trigger (both sizes): `ui-button ui-button--secondary`, `padding: 0.45rem 0.75rem`, contents: Images icon (16, muted), current name ("All media" or the album name, 0.95rem), album count when `typeof mediaCount === 'number'` (0.8rem muted; none for All media), ChevronDown 14. Accessible name `Album: <name>` plus `, <n> items` when a count exists. `aria-expanded` mirrors the open state; open state background `rgba(77, 168, 255, 0.2)`.

- Items: All media, separator, then every album in the current order. Each item `role="menuitemradio"` with `aria-checked` (true on the current one): 16px check slot (Check icon in `var(--accent)` on the current one), name (truncate with ellipsis, `title` = full name), count right-aligned muted. Current item 700 weight.
- Extend `DropdownMenu` so `menuitemradio` items take part in arrow keys/Home/End/type-ahead (today it only queries `[role="menuitem"]`), and let a menu open with focus on its checked item. Existing DropdownMenu tests must still pass.
- Choosing an item calls `onSelectAllMedia` / `onSelectAlbumById` (these already reset selection and close the duplicates view), closes the menu and returns focus to the trigger. Escape and click outside close it and return focus to the trigger (DropdownMenu behaviour).
- No albums: the menu holds All media only.

Phone: the trigger has `aria-haspopup="dialog"` and opens a full-screen list, built like the phone dockspace list (`dockspace-switcher-screen`, reuse its CSS or move it to a shared class):

- `<nav aria-label="Albums">` list of buttons: Images icon, name, count (none for All media), ChevronRight; the current row `aria-current="true"` with the switcher's current-row style (tint + 3px left accent bar).

### 6. Tiles (`VirtualizedMediaGrid.tsx`, `mediaGridConfig.ts`, ui.css/layout.css)
- `MEDIA_GRID_GAP_PX = 0`. Square tiles: `columnCount = max(1, floor(width / minColumnWidthPx))`, column width = `width / columnCount`, and the row stride = that column width (replaces fixed `rowHeightPx`; keep `minColumnWidthPx` 132 / 190 / 248 per size). Recompute on resize; keep T-0029's stride-based spacer math (stride = row height when the gap is 0) and update the scroll anchoring test.
- `.media-card`: no border, `border-radius: 0`, no background frame, no `transform` or `border-color` transition. States are drawn by an `::after` overlay (`inset: 0; pointer-events: none`) so nothing moves:
  - hover (pointer only, `@media (hover: hover)`): `background: rgba(255, 255, 255, 0.1)`;
  - `:focus-visible`: `outline: none`; overlay `box-shadow: inset 0 0 0 2px var(--accent), inset 0 0 0 4px #fff`;
  - selected (`data-selected="true"`): `background: rgba(77, 168, 255, 0.24); box-shadow: inset 0 0 0 3px var(--accent)`; selected + focus: `inset 0 0 0 3px var(--accent), inset 0 0 0 5px #fff`.
- Selection indicator: 1.35rem circle top right (0.45rem inset), `1.5px solid rgba(255, 255, 255, 0.85)` on `rgba(15, 16, 20, 0.55)`; selected: `var(--accent-strong)` fill, white border, white Check icon (14px, replaces the "✓" text).
- Placeholder tiles (no thumbnail) keep the Image/Film icon on the current tint; the tint fills the whole tile.
- Respect `prefers-reduced-motion` (no transitions needed at all; the overlay can change instantly).

## Security review (round 1)

Scope: frontend only (`apps/web`: new `GalleryAlbumMenu.tsx` and `GalleryOptionsMenu.tsx`, `DockspaceMediaWorkspace.tsx`, `DropdownMenu.tsx`, `UploadsCard.tsx`, the media controller, grid config, CSS and tests). No backend handlers, routes, CDK, IAM, S3 or package.json / package-lock.json changes.

No findings.
- Album names, file names and the upload error message are rendered as JSX text or a `title` attribute (escaped by React); no `dangerouslySetInnerHTML`, `innerHTML` or URLs built from data.

- Album switching calls the existing `onSelectAllMedia` / `onSelectAlbumById` with ids from the albums list the API returned; no new API calls, and no tokens or file contents logged, stored or put in URLs.
- The `DropdownMenu` type-ahead reads only item `textContent` to move focus; `document.body.style.overflow` is restored on close of the phone album screen.
