# T-0032 Gallery preview returns focus to its tile on close
Issue: #70
Request: #65
Origin: T-0029
Status: new

## Goal
In the media gallery, closing the full-screen preview (Escape, the close button, Close, or the backdrop) leaves keyboard focus on `<body>`, so a keyboard or screen reader user loses their place. Focus should go back to the tile that opened the preview, or to the tile of the item shown last after previous/next. Already on main: `apps/web/src/components/files/FileViewerDialog.tsx` (variant `media-fullscreen`, used by `DockspaceMediaPage`) has no code that returns focus on close. Found while testing T-0029 (#66), round 1, finding 2.

Notes: the gallery is virtualized (`VirtualizedMediaGrid.tsx`), so the tile may not be rendered when the preview closes. Follow the engineering-lessons focus rule: end the fallback chain with an always-mounted element (the scroll box has `tabIndex={-1}` after T-0029). Build on main after T-0029 (PR #68) is merged, and coordinate with T-0030 (gallery layout).

## Acceptance criteria
1. On All media and in an album view, open the preview from a tile with the keyboard (Enter), then close it with Escape, the close control, Close, or a backdrop click: focus goes to the tile that opened it, with the visible `:focus-visible` ring for keyboard users.
2. After moving through items with Next/Previous (buttons or arrow keys) and then closing, focus goes to the tile of the item shown last. If that tile is outside the rendered (virtualized) window, the grid scrolls it into view and focuses it. If it cannot be rendered, focus goes to an always-mounted element (for example the grid scroll box). Focus never stays on `<body>`.
3. Opening with a mouse click and closing does not show a focus ring on the tile (`:focus-visible` only).
4. Preview, previous/next, multi-select, grid size toggle and infinite scroll keep working as before.
5. Unit tests cover each close path and the after-previous/next case, including the tile outside the render window. Build, typecheck and tests pass.
