# T-0036 Gallery shows a new upload's thumbnail without a reload
Issue: #79
Request: #65
Origin: T-0033
Status: new

## Goal
After T-0033, a file uploaded from the media gallery appears in the gallery right away, but its tile shows the generic placeholder icon instead of its thumbnail until the page is reloaded or the tab regains focus. The single post-batch `GET /media` (T-0033's `useRefreshMediaAfterUploads`, wired through `onBatchComplete` in `useDockspaceUploadDialog`) returns before the asynchronous thumbnail Lambda has written the thumbnail, so the new item has no `thumbnail` and nothing fetches again. Found while testing T-0033 (#74), round 1, finding 1.

Notes: the gallery query is infinite and paged (120 per page), so a plain invalidation re-requests every loaded page. Prefer a targeted, bounded follow-up (for example refetch page 1 or the new items only, a few times with backoff, while recently uploaded image items have no thumbnail). Videos or files that never get a thumbnail must not cause endless polling. T-0030 and T-0034 touch the same gallery files; rebase on main before the PR.

## Acceptance criteria
1. After an upload from the media gallery, the new tile shows its thumbnail within a few seconds of the thumbnail being generated, with no reload or tab switch (desktop and phone).
2. The follow-up is bounded: it runs only while recently uploaded items still have no thumbnail, and stops once they have one or after a time limit.
3. T-0033's behaviour (one gallery refetch per upload batch, not one per file) and the T-0029/T-0031 paging behaviour (one request at a time, status text only near the end) are unchanged.
4. Tests cover the thumbnail follow-up and its stop conditions. Build, typecheck and tests pass.
