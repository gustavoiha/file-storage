# T-0034 Gallery "Move to trash" dialog closes without waiting for the gallery refetch
Issue: #75
Request: #65
Origin: T-0031
Status: testing

## Goal
In the media gallery, after Trash selected and Move to trash, the dialog stays on "Moving..." until every loaded gallery page has been fetched again. Already on main: `useTrashFilesBatch` in `apps/web/src/hooks/useFiles.ts` awaits all its invalidations in `onSuccess`, including `media`, whose refetch re-requests each loaded page one after another (120 items per page). With several pages loaded or a slow network this is several seconds after the trash request already succeeded. Found while testing T-0031 (#69), round 1, finding 2.

Notes: the trashed tiles should still leave the gallery (refetch in the background or remove them from the cache); errors of the trash request itself must still keep the dialog open with its error. Check the other callers of `useTrashFilesBatch` (files page) for the same wait. Coordinate with T-0030 (gallery layout), which touches the same files.

## Acceptance criteria
1. The Move to trash dialog closes (and the selection clears) as soon as the trash request succeeds, without waiting for the gallery refetch, on desktop and phone.
2. The trashed items leave the gallery without a reload; the gallery refetch runs in the background (T-0031's status text shows only near the end of the loaded media).
3. A failed trash request keeps the current behaviour (dialog stays open with the error, focus per the engineering lessons).
4. A test holds the media refetch and expects the dialog to close before it ends. Build, typecheck and tests pass.
