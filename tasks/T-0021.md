# T-0021 Keep focus in the trash list after a restore or purge
Issue: #46
Request: #5
Origin: T-0019
Status: review

## Goal
On the trash page (`apps/web/src/pages/TrashPage.tsx`, flat `FileList`), a successful Restore, or a Purge confirmed in its dialog, removes the row, and keyboard focus falls to `<body>`. The next Tab starts again from the top of the page, far from where the user was in a long trash list. T-0012 fixed the same problem for Move to Trash in the file list; the trash page should behave the same way.

## Acceptance criteria
1. After a successful Restore of a trashed item, focus moves to the next row's Restore button, else the previous row's Restore button, else a fallback in the trash card (e.g. the list or the empty-trash message, focusable with `tabIndex={-1}`). Never `body`.
2. After a successful Purge confirmed in the Purge dialog, focus follows the same rule as criterion 1 once the dialog closes.
3. A failed Restore or Purge keeps today's behavior (focus stays on the row's control, or returns to the opener when the dialog is cancelled or closed); the per-row restore errors and Dismiss focus from T-0019 still work.
4. The focused fallback shows a visible focus ring for keyboard users (`:focus-visible`), as T-0010 does for the file list.
5. Unit tests cover: focus after a successful restore of a middle row, of the last row, and of the only row; focus after a successful purge. Build, typecheck and tests pass.
