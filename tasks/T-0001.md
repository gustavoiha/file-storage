# T-0001 File navigability: single folder navigation, parent-folder context, side preview pane
Issue: #4
Status: new

## Goal
Make navigating files in a generic dockspace easier to follow. Today the folder structure appears in two places: the sidebar directory tree (`DockspaceSidebar`) and the folder/file list in the main panel (`FileList` on `DockspaceFilesPage`). File previews open in a modal (`FileViewerDialog`). The human wants:
1. Only one place that shows the folder structure.
2. The previous (parent) folder stays visible after opening a nested folder.
3. File preview shown in a panel on the right instead of a dialog popup.

## Acceptance criteria
- Generic dockspaces show the folder hierarchy in exactly one place. The sidebar tree and the main-panel folder listing no longer duplicate each other.
- After opening a nested folder, the parent folder's contents (or an equivalent view of the previous level) stay visible next to the current folder, for example as Finder-style columns or a persistent parent pane. Design decides which.
- Selecting or opening a file shows its preview in a right-hand pane inside the page layout, not in a modal. The pane can be closed, and the folder view stays usable while it is open.
- Existing file operations keep working in the new layout: upload (files and folders), add folder, rename, move (multi-select), trash folder or file, download (file and folder).
- Media dockspaces (album-based, `DockspaceMediaPage`) are out of scope unless design says otherwise.
- The layout works at narrow or phone widths (for example, the preview pane takes over the view, with a back control).
- Existing web tests are updated or extended to cover the new navigation and preview behavior.
