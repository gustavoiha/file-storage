# T-0008 Desktop right-click menu takes keyboard focus
Issue: #20
Request: #5
Status: filtering
Origin: T-0007

## Goal
On desktop (>900 px), right-clicking a file or folder row opens its `Actions for {name}` menu, but focus stays on the row, so the arrow keys (T-0007) do nothing until the user tabs in, and Escape leaves focus on body. On main, `useRowMenu` in apps/web/src/components/files/FileList.tsx moves focus into the menu only in the phone layout. Make the desktop row-opened menu (right-click, ContextMenu key, Shift+F10) behave like the phone one.

## Acceptance criteria
1. On desktop, when the row menu opens from a right-click, the ContextMenu key or Shift+F10 on a focused row, focus moves to the first menu item, and ArrowDown/ArrowUp/Home/End work at once.
2. Escape closes it and returns focus to the row it was opened from (not body). A click outside closes it without moving focus to body.
3. Menus opened from the `⋯` trigger and the phone long-press menu keep their current behaviour.
4. No new serious or critical axe violations. Web tests cover focus on open and on Escape for the desktop right-click/Shift+F10 path.
